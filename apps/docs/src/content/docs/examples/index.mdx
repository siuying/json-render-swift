They are bundled into the FormDemo app as offline examples, loaded by the Swift tests, and rendered by the SDK's render smoke tests. The four below each have their own page with a walkthrough of the interesting elements and the full spec. A fifth, `sales-review.json`, puts a bar chart and a line chart above its fields; see [Charts](/json-render-swift/charts/). For PDF documents (invoice, report, resume, letter, statement), see [PDF examples](/json-render-swift/pdf/examples/).

## What each example covers

| Feature | registration | event-rsvp | feedback-survey | shipping-address |
|---|:-:|:-:|:-:|:-:|
| `required`, `email`, `minLength`, `maxLength` | ✓ | ✓ | ✓ | ✓ |
| `pattern` | ✓ | | | ✓ |
| Cross-field `matches` with `$state` | ✓ | | | |
| `requiredIf` | | ✓ | ✓ | |
| `validateOn: "blur"` | ✓ | ✓ | ✓ | ✓ |
| `visible` on a field | ✓ | ✓ | ✓ | ✓ |
| `visible` on a whole `Section` | | ✓ | | |
| `$template` | ✓ | ✓ | | ✓ |
| `$cond` | | ✓ | ✓ | |
| `LabeledContent` summary | | ✓ | | ✓ |
| `openURL` | ✓ | | | |
| `resetForm` with `confirm` | | | ✓ | |
| `Stepper`, `DatePicker` | | ✓ | | |
| `Slider` | | | ✓ | |
| Nested state paths | | | | ✓ |

Every example submits with the same binding, `{ "action": "submit", "params": { "data": { "$state": "/form" } } }`, so your `submit` handler receives the whole `/form` object once every visible field passes.

None of the four use `watch`, `showAlert` or a custom action such as the demo's `log`. See [Watchers](/json-render-swift/watchers/) and [Actions](/json-render-swift/actions/) for those.

## The recorded stream

`fixtures/specs/registration.jsonl` is the registration form as a model would stream it: 23 lines, one [RFC 6902](https://www.rfc-editor.org/rfc/rfc6902) patch per line. Compiled with `SpecStreamCompiler`, it produces exactly `registration.json`; the demo's pipeline tests check this.

The demo's **Replay stream** button plays this file through the same pipeline as a live generation, split into chunks of 4 to 27 characters with 25 ms between them, so you can watch a form build without an API key. See [Registration](/json-render-swift/examples/registration/#the-recorded-stream) for the first lines of the file and [Life of a Prompt](/json-render-swift/demo/prompt-lifecycle/) for the pipeline.

## Loading an example in the demo

In FormDemo, open the **Examples** menu (top left, or the button on the empty screen) and pick a form. Examples load the finished spec directly, so the JSONL tab stays empty for them.

To open the app on a specific example, pass `-example <id>` as a launch argument, where `<id>` is `registration`, `event-rsvp`, `feedback-survey` or `shipping-address`:

```bash
xcrun simctl launch booted dev.jsonrender.FormDemo -example event-rsvp
```

[Running the Demo](/json-render-swift/demo/running/#launch-arguments) lists the other launch arguments.

## How the fixtures are tested

Because the same files feed the app and the tests, a change to a fixture is checked on both sides:

| Suite | What it checks |
|---|---|
| `packages/swift/test/catalog.test.ts` | Each spec passes `validateSwiftUISpec` with no issues, and survives `catalog.validate` unchanged. |
| `packages/swift/test/stream.test.ts` | `registration.jsonl` compiles to `registration.json`, for whole-file and 1, 7, 64 and 333-character chunks. |
| `SpecDecodingTests` (Swift) | Each spec decodes, its root is a `Form`, every element type has a standard renderer, every child key exists, and it round-trips through `Codable`. |
| `RenderingTests` (Swift) | Each spec mounts in a real hosting view, before and after `validateAll()`. Every line-by-line prefix of `registration.jsonl` renders. |
| `GenerationPipelineTests` (FormDemo) | Each example loads into a fresh `FormSession`; the replayed stream produces exactly `registration.json`. |

## Using an example in your app

Each spec is a plain JSON file. Add it to your app target, decode it with `Spec(jsonData:)` and render it with a `FormSession` and `JSONRenderView`. Each example page has the code. <Badge text="No API key needed" variant="tip" />
