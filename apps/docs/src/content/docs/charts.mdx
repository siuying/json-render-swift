Four chart components plot an array of records: `BarChart` compares categories, `LineChart` shows a trend, `AreaChart` shows cumulative or volume trends, and `PieChart` shows the share of a whole. Both the forms catalog and the PDF catalog have them, with the same props. `JSONRenderSwiftUI` draws them with Swift Charts, and `JSONRenderPDF` draws them with Core Graphics and Core Text. Both renderers process the data the same way.

## Bar, line and area charts

<ComponentTable name="BarChart" />

`LineChart` and `AreaChart` have the same props. In the PDF catalog, optional props are nullable: leave them out or set them to `null`.

- `data`: an array of objects, usually `{ "$state": "/sales" }`. An object with a `data` array (`{ "data": [...] }`) works too.
- `xKey`: the field that names each bar or point.
- `yKey`: the numeric field. Numbers and numeric strings (`"450.50"`) are accepted.
- `aggregate`: `"sum"`, `"avg"` or `"count"`. Leave it out to plot each record as it is.
- `color`: a hex color such as `"#2563eb"`. SwiftUI uses the app's tint by default, and PDF uses `#2563eb`.
- `height`: the chart's height in points, 300 by default and at least 200. In a PDF this includes the axis labels.
- `title`: drawn in bold above the chart.

### Data

Without `aggregate`, every record is one bar or point, in array order, labelled with its `xKey` value. A record whose `yKey` is not a number is skipped. Repeated labels stay separate bars.

With `aggregate`, records are grouped by their `xKey` value and the groups are sorted by key:

| `aggregate` | Value of each group | Value name |
| --- | --- | --- |
| `sum` | the sum of `yKey` (non-numeric values count as 0) | `yKey` |
| `avg` | the mean of `yKey` (non-numeric values count as 0) | `yKey` |
| `count` | the number of records | `count` |

A record without an `xKey` value goes in the group `"unknown"`.

**Dates.** When the first record's `xKey` value is an ISO date (`2025-03-05` or `2025-03-05T09:15:00Z`), dates are labelled `MMM dd` in English (`Mar 05`), using the calendar day as written. With `aggregate`, records are grouped by that day, so `count` gives "orders per day".

`ChartData(props:)` in `JSONRenderSwiftUI` does this processing. It is public, so a custom chart component can use it too.

## Pie charts

<ComponentTable name="PieChart" />

- `data`: as for the other charts.
- `nameKey`: the field that names each slice.
- `valueKey`: the numeric field that sizes it.
- `aggregate`: `"sum"`, `"avg"` or `"count"`, grouping records by `nameKey` as above.
- `donut`: `true` cuts out the middle half of the pie.
- `colors`: hex colors used for the slices in turn, starting again after the last. Without it (or when none of the entries is a hex color), slices use the default palette: `#2563eb`, `#16a34a`, `#f59e0b`, `#dc2626`, `#7c3aed`.
- `legend`: `false` hides the legend. By default each slice gets a row below the pie with its color, name and percentage.
- `height`: the pie's height in points, 300 by default and at least 200. The legend goes below it.

**Slices.** Without `aggregate`, every record with a positive value is one slice, in array order. Zero, negative and non-numeric values are left out. A record without a name is labelled `Segment N`, where N is its position in `data`. With `aggregate`, records are grouped by their name exactly as written (dates are not merged by day) and sorted by name; a record without a name goes in `"unknown"`. `sum` and `avg` use only the positive values, so a name with none is left out, and `count` counts every record of a name whatever its value. When no slice is left, the chart shows "No data available". Slices start at 12 o'clock and go clockwise. Percentages are rounded to whole numbers, so they may add up to 99% or 101%, and a share under half a percent shows as `<1%`.

## Rendering

**SwiftUI.** `BarChart` draws one `BarMark` per point with rounded corners. `LineChart` draws a `LineMark` with monotone interpolation, 2 pt wide, with no point markers. `AreaChart` draws the same line over an `AreaMark` filled down to zero in the chart color at 25% opacity. These three show horizontal gridlines with value labels and one x-axis label per category. `PieChart` draws one `SectorMark` per slice with a small gap between slices, and lists the legend below. When there is no data, a chart shows "No data available".

**PDF.** A chart is one block: its title, plot and legend move to the next page together and are never split. A chart taller than the page gets a shorter plot (down to 120 pt) so it fits on one page with its title and legend; when a legend is too long even then, its rows continue on the next pages. Value labels sit to the left of horizontal gridlines, and category labels sit under the plot. When labels would overlap, every second (or third, …) label is drawn. Bars fill 80% of their band and have 4 pt rounded corners. Negative values hang below the zero line. Lines are monotone curves that never overshoot between points, and an area is filled between its line and the zero line. A pie is the largest circle that fits the plot, centred, with a 1 pt gap between slices; legend names wrap within the chart's width. A chart inside a `Row` shares the row's width like other children.
