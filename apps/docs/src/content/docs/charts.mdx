Four chart components plot an array of records: `BarChart` compares categories, `LineChart` shows a trend, `AreaChart` shows cumulative or volume trends, and `PieChart` shows the share of a whole. Both the forms catalog and the PDF catalog have them, with the same props. `JSONRenderSwiftUI` draws them with Swift Charts, and `JSONRenderPDF` draws them with Core Graphics and Core Text. Both renderers process the data the same way.

## Bar, line and area charts

<ComponentTable name="BarChart" />

`LineChart` and `AreaChart` share the base series props below. `labelKey`, `horizontal`, `maxCategories` and `otherLabel` apply to bars; pies also support the category cap. In the PDF catalog, optional props are nullable: leave them out or set them to `null`.

- `data`: an array of objects, usually `{ "$state": "/sales" }`. An object with a `data` array (`{ "data": [...] }`) works too.
- `xKey`: the field that names each bar or point.
- `yKey`: the numeric field. Numbers and numeric strings (`"450.50"`) are accepted.
- `aggregate`: `"sum"`, `"avg"` or `"count"`. Leave it out to plot each record as it is.
- `color`: a hex color such as `"#2563eb"`. SwiftUI uses the app's tint by default, and PDF uses `#2563eb`.
- `height`: the chart's height in points, 300 by default and at least 200. In a PDF this includes the axis labels.
- `title`: drawn in bold above the chart.

### Data

Without `aggregate`, every record is one bar or point, in array order, labelled with its `xKey` value. A record whose `yKey` is not a number is skipped. Repeated labels stay separate bars.

With `aggregate`, records are grouped by their `xKey` value and the groups are sorted by key:

| `aggregate` | Value of each group | Value name |
| --- | --- | --- |
| `sum` | the sum of `yKey` (non-numeric values count as 0) | `yKey` |
| `avg` | the mean of `yKey` (non-numeric values count as 0) | `yKey` |
| `count` | the number of records | `count` |

A record without an `xKey` value goes in the group `"unknown"`.

**Dates.** When the first record's `xKey` value is an ISO date (`2025-03-05` or `2025-03-05T09:15:00Z`), dates are labelled `MMM dd` in English (`Mar 05`), using the calendar day as written. With `aggregate`, records are grouped by that day, so `count` gives "orders per day".

`ChartData(props:)` in `JSONRenderSwiftUI` does this processing. It is public, so a custom chart component can use it too.

## Pie charts

<ComponentTable name="PieChart" />

- `data`: as for the other charts.
- `nameKey`: the field that names each slice.
- `valueKey`: the numeric field that sizes it.
- `aggregate`: `"sum"`, `"avg"` or `"count"`, grouping records by `nameKey` as above.
- `donut`: `true` cuts out the middle half of the pie.
- `colors`: hex colors used for the slices in turn, starting again after the last. Without it (or when none of the entries is a hex color), slices use the default palette: `#2563eb`, `#16a34a`, `#f59e0b`, `#dc2626`, `#7c3aed`.
- `legend`: `false` hides the legend. By default each slice gets a row below the pie with its color, name and percentage.
- `height`: the pie's height in points, 300 by default and at least 200. The legend goes below it.

**Slices.** Without `aggregate`, every record with a positive value is one slice, in array order. Zero, negative and non-numeric values are left out. A record without a name is labelled `Segment N`, where N is its position in `data`. With `aggregate`, records are grouped by their name exactly as written (dates are not merged by day) and sorted by name; a record without a name goes in `"unknown"`. `sum` and `avg` use only the positive values, so a name with none is left out, and `count` counts every record of a name whatever its value. When no slice is left, the chart shows "No data available". Slices start at 12 o'clock and go clockwise. Percentages are rounded to whole numbers, so they may add up to 99% or 101%, and a share under half a percent shows as `<1%`.

`PieChartData(props:)` does this processing, and `ChartColors.palette` holds the default palette.

## Rendering

**SwiftUI.** `BarChart` draws one `BarMark` per point with rounded corners. `LineChart` draws a `LineMark` with monotone interpolation, 2 pt wide, with a point marker for a numeric run of one. `AreaChart` draws the same line over an `AreaMark` filled down to zero in the chart color at 25% opacity. These three show horizontal gridlines with value labels and one x-axis label per category. `PieChart` draws one `SectorMark` per slice with a small gap between slices, and lists the legend below. When there is no data, a chart shows "No data available".

**PDF.** A chart is one block: its title, plot and legend move to the next page together and are never split. A chart taller than the page gets a shorter plot (down to 120 pt) so it fits on one page with its title and legend; when a legend is too long even then, its rows continue on the next pages. Under a very long title the plot gets shorter still (down to 40 pt) to stay on the title's page; only a title that leaves less room than that flows on as text, with the plot after it. Value labels sit to the left of horizontal gridlines, and category labels sit under the plot. When labels would overlap, every second (or third, …) label is drawn. Bars fill 80% of their band and have 4 pt rounded corners. Negative values hang below the zero line. Isolated numeric samples in lines and areas draw a point marker. Lines are monotone curves that never overshoot between points, and an area is filled between its line and the zero line. A pie is the largest circle that fits the plot, centred, with a 1 pt gap between slices; legend names wrap within the chart's width. A chart inside a `Row` shares the row's width like other children.

For pre-grouped bars, set `labelKey` to show a field other than the category
key. For example, `xKey: "key", labelKey: "label", yKey: "value"` displays
`label` while keeping the records' order. With `aggregate`, records are grouped
and sorted by `xKey`, and the first record in each group supplies its label.
When the label is missing or null, the category key is displayed.

## Horizontal bars

Set `horizontal: true` on `BarChart` to put categories on the vertical axis and values on the horizontal axis. Labels wrap within the left half of the chart; use a taller `height` for many long labels. The default is vertical.

```json
{ "type": "BarChart", "props": { "horizontal": true, "xKey": "region", "yKey": "sales", "data": [{ "region": "Western region", "sales": 12 }] } }
```

## Limiting categories

BarChart and PieChart accept `maxCategories`, a positive integer including the final Other slot, and `otherLabel`, default `"Other"`. Processing first filters and aggregates as described above, keeping input order without aggregation and key order with aggregation. When the result exceeds the cap, retain the `maxCategories - 1` entries with the largest numeric values. Ties retain the earlier entry. Display the retained entries in their existing order, then append Other. Other sums the folded values for sum, count and unaggregated data. With `avg`, it averages the folded source rows, weighted by row count, using the numeric-value rules for that chart. `maxCategories: 1` combines everything. Existing groups named Other remain separate. Omit the cap for existing behavior.

```json
{ "type": "BarChart", "props": { "maxCategories": 2, "otherLabel": "Rest", "xKey": "region", "yKey": "sales", "data": [{ "region": "East", "sales": 12 }, { "region": "West", "sales": 8 }, { "region": "North", "sales": 4 }] } }
```

### Pre-folded Other groups

All four charts accept `otherKey`, the name of a source field whose truthy value
marks a datum as Other. Missing fields, null, false, zero and empty strings are
false; other values, including arrays and objects, are true. Bar and pie charts
apply `otherColor` to these groups as they do to generated Other groups.
Without `aggregate`, labels and positions stay in input order. With aggregation,
a group is Other when any contributing record has the flag; normal key sorting
still applies. Pie sum and average inspect only positive contributing records.
A category merely named "Other" is still ordinary unless flagged.

When a cap is exceeded, only ordinary groups compete for the largest
`maxCategories - 1` slots. All explicit Other groups merge with the remaining
groups into one final Other slot, named by `otherLabel`. The existing cap rules
apply: sum the displayed values, or for `avg`, average the contributing source
rows. Pre-computed averages therefore need source-row weights applied by the
consumer before charting. When the cap is not exceeded, explicit Other groups
keep their positions, labels and values.

With `otherKey` configured, every press `$datum` includes `isOther`, true or false.
Original flag fields remain in `records`. Omitting `otherKey` preserves existing
processing and payloads. See `fixtures/charts/bar-explicit-other.json`.

```json
{ "type": "BarChart", "props": { "otherKey": "rest", "otherColor": "#888888", "xKey": "region", "yKey": "sales", "data": [{ "region": "West", "sales": 12 }, { "region": "Other", "sales": 8, "rest": true }] } }
```

## Live updates

Props may resolve from live state, including `horizontal`. Horizontal and vertical series use separate chart views, and a changed processed dataset creates a fresh chart. Swift Charts therefore never reuses a categorical axis as a numeric axis during an update. Empty arrays show the empty message; non-numeric values follow the filtering rules above. No extra prop is required. See `fixtures/charts/bar-live.json` for state bindings.

## Accessibility

Each mark exposes its category and numeric value. Pie marks also announce their percentage. Charts provide an audio graph through SwiftUI's `accessibilityChartDescriptor`, with every processed value and the chart title. A default summary states the category count and value range; set `accessibilitySummary` to describe the takeaway instead. Horizontal charts read top to bottom; pies read clockwise. Titles and legends use Dynamic Type text styles, and legend swatches scale with the text. PDF accepts the summary prop but does not create an interactive audio graph.

```json
{ "type": "PieChart", "props": { "accessibilitySummary": "East accounts for three quarters of sales.", "nameKey": "region", "valueKey": "sales", "data": [{ "region": "East", "sales": 3 }, { "region": "West", "sales": 1 }] } }
```

## Press actions

All four SwiftUI charts emit `on.press` once after a tap. `chartOverlay` uses Swift Charts' `ChartProxy` to resolve a category with `value(atX:)` or `value(atY:)`, or a pie angle with `angle(at:)` and `value(atAngle:)`. Bars also check the mark's band and numeric extent; taps outside the plot or inside a donut hole do nothing. Line and area charts select the category under the tap. A `SpatialTapGesture` completes only on a tap, so dragging and scrolling do not fire actions. Each mark has a separate native accessibility element whose Activate action sends the same payload. Its frame comes from ChartProxy, so VoiceOver focus, automated taps and touch hit testing use the same geometry. Native activation is tested in a hosted chart; UI tests separately check VoiceOver traversal and taps through those frames.

The datum is `{ "index": 0, "label": "West", "value": 12, "records": [...] }`, with `fraction` added for pies. `index` is the displayed position. `records` contains the source records contributing to that mark, including all records in a capped Other group. Without aggregation it has one record. Pie sum and average include only positive contributing records, while count includes all records. Source fields are preserved inside `records`. This envelope keeps actions consistent for raw, aggregated and capped charts.

`{ "$datum": "" }` resolves the whole datum; a JSON Pointer such as `{ "$datum": "/label" }` selects one field. References are supported only as top-level param values, not nested inside objects or arrays. Without a datum payload they resolve to null. PDF ignores actions and its catalog does not advertise press.

```json
{
  "type": "BarChart",
  "props": { "horizontal": true, "xKey": "region", "yKey": "sales", "data": [{ "region": "West", "sales": 12 }] },
  "on": { "press": { "action": "setState", "params": { "statePath": "/selected", "value": { "$datum": "" } } } }
}
```

The hit testing follows Apple's [ChartProxy API](https://developer.apple.com/documentation/charts/chartproxy).

## Unknown and formatted values

Series charts accept `missing: "show"` to retain non-numeric or null values as neutral square markers annotated `n/a`. Their datum value is `null`; records and category labels remain available for actions. Missing marks always use a numeric zero position and are excluded from audio-graph numeric samples. Lines and areas break at missing samples. The default `missing: "skip"` preserves existing behavior. With aggregation, a group with no numeric rows becomes n/a in show mode; mixed groups retain the aggregation rules above. Caps rank known values before unknowns. A folded group with only unknowns remains n/a. Pie charts continue to require positive values.

`valueFormat` formats VoiceOver values and mark annotations in both renderers, after aggregation and capping. It accepts `{ "style": "number" }`, `{ "style": "percent" }`, or `{ "style": "currency", "currency": "HKD" }`, with an optional locale identifier. It never changes numeric axes or datum values. `otherColor` is an optional hex color for an Other group in bars and pies; an ordinary source category named Other keeps its normal color. Without `height`, horizontal charts use about 34 pt per visible category plus 32 pt for axes, with a 200 pt minimum. An explicit height takes precedence.

```json
{ "type": "BarChart", "props": { "horizontal": true, "missing": "show", "valueFormat": { "style": "currency", "currency": "HKD" }, "otherColor": "#888888", "xKey": "category", "yKey": "amount", "data": [{ "category": "Known", "amount": 12 }, { "category": "Unknown", "amount": null }] } }
```

FormDemo's **Chart data options** example demonstrates n/a drill-down, currency annotations and a gray Other group.
