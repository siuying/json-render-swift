## Where the specs come from

**Invoice, report, resume and letter** are json-render's sample documents. `packages/swift/scripts/extract-pdf-examples.ts` extracts them from a json-render checkout instead of copying them by hand:

```sh
# JSON_RENDER_DIR defaults to ../json-render next to this repository
pnpm --filter @json-render/swift extract:pdf-examples
```

The script writes `fixtures/pdf/<name>.json` and adds `"children": []` to every leaf element that has no `children` field, because the spec schema requires it.

**`statement.json`** is written for this repository to exercise the data features: `state`, a `repeat` nested inside another through an item-relative `statePath`, `$item`, `$index`, `$template` with bare and absolute names, `$cond`, `visible` with `not` and with `$item`, a two-page flow and `PageNumber` with a total.

**`application-form.json`** is written for this repository to exercise the [fillable form components](/json-render-swift/pdf/forms/): every field type, nested `FieldSet`s, values from `state`, and a `repeat` whose fields get per-item names.

**`sales-report.json`** is written for this repository to exercise the [charts](/json-render-swift/charts/): a `BarChart` with inline data, then two `Row`s of charts over the same `$state` orders: a `LineChart` and a `BarChart` (`count` and `sum`), then a donut `PieChart` of orders per channel and an `AreaChart` of order value per day.

**`statement.jsonl`** and **`application-form.jsonl`** are the same specs as the JSONL patch streams a model would emit, generated from the JSON files:

```sh
pnpm --filter @json-render/swift gen:pdf-stream
```

`scripts/gen-pdf-stream.ts` emits `/root`, then every element top-down from the root, each top-level `state` key right after the first element that references it, and arrays as `[]` followed by one patch per item, which is the order the PDF prompt asks for. They are generated, not recorded from a model. The statement's 62 patches and the application form's 93 compile back to their JSON specs exactly, which TypeScript tests check (and a Swift test for the statement).

## Screenshots

The page images on these pages are `docs/screenshots/pdf/*.png`. Regenerate them from `swift/JSONRender`:

```sh
JSONRENDER_PDF_SCREENSHOTS=1 xcrun swift test --filter PDFScreenshots
```

The opt-in suite in `Tests/JSONRenderPDFTests/PDFScreenshotTests.swift` renders every fixture with the `.placeholders` image loader (deterministic, no network), rasterizes the first page and the first continuation page (when there is one) to PNG at 1200 pixels high on white with Core Graphics, and writes `<name>-page1.png` and `<name>-page2.png`. It also writes each PDF to the temporary directory as `jsonrender-<name>.pdf`. Without the environment variable, the suite is skipped.

## What the tests check

The PDF test suites run every fixture: each renders at least one page with every drawn item inside the page bounds, and the bridge validates each against the PDF catalog with no errors. Fixture-specific tests check the invoice's text and metadata, the statement's page count, every transaction description and the `Page N of M` text on each page, hyphenated line breaks in the letter and report, and that every streamed prefix of `statement.jsonl` renders without throwing. The form tests render the application form, check its field tree, fill it through PDFKit and read the values back with `PDFFormReader`.
